## 1. Создать свой репозиторий

Один репозиторий на весь семестр. Имя: `cv-2026-` плюс фамилия латиницей строчными буквами. Иванов создаёт `cv-2026-ivanov`, Щербакова создаёт `cv-2026-shcherbakova`. Репозиторий должен быть **публичным**: иначе преподаватель его не увидит.

1. Войдите на [github.com](https://github.com), справа сверху нажмите **+** → **New repository**.
2. **Repository name**: `cv-2026-familiya`.
3. Выберите **Public**.
4. Галочку **Add a README file** не ставьте, `.gitignore` и лицензию не выбирайте. Всё это вы возьмёте из шаблона.
5. Нажмите **Create repository**.

### Шаблон репозитория

В репозитории курса лежит готовый шаблон: [templates/student-repo/](../templates/student-repo/). В нём четыре файла:

| Файл | Зачем |
| --- | --- |
| `README.md` | Оглавление вашего репозитория: ФИО, группа, вариант, таблица работ |
| `.gitignore` | Список того, что git не должен загружать: данные, веса моделей, кэш |
| `requirements.txt` | Пакеты, которые нужны вашему коду |
| `lab_README_template.md` | Заготовка отчёта по лабе с пятью обязательными разделами |

Как получить файлы шаблона:

1. Откройте [главную страницу репозитория курса](https://github.com/ykvnkm/computer-vision-course), нажмите зелёную кнопку **Code** → **Download ZIP**.
2. Распакуйте архив и откройте папку `templates/student-repo/`.
3. Положите эти файлы в корень своего репозитория одним из способов ниже.
4. Откройте `README.md` и впишите ФИО, группу и номер варианта.

> Файл `.gitignore` начинается с точки, и macOS по умолчанию его прячет. В Finder нажмите **Cmd + Shift + .** (точка), чтобы увидеть скрытые файлы. В Windows включите в Проводнике **Вид** → **Показать** → **Скрытые элементы**.

Когда начинаете новую лабу, создайте папку `lab0N/`, скопируйте в неё `lab_README_template.md` и переименуйте копию в `README.md`.

После создания репозитория впишите ссылку на него в общую таблицу группы, её даст преподаватель.

## 2. Выбрать способ работы

| Где вы пишете код | Как загружать на GitHub |
| --- | --- |
| Kaggle или Colab | [Через сайт GitHub](#загрузка-файлов-через-сайт-github): скачали `.ipynb` и картинки, перетащили в браузер |
| Локально, Windows или macOS | GitHub Desktop: программа с кнопками, без терминала |
| Локально, Linux или вы привыкли к терминалу | [git в терминале](#git-в-терминале) и вход через `gh auth login` |

Все три способа дают одинаковый результат: коммит на GitHub со временем. Можно комбинировать, например, иногда загружать через сайт, а иногда через Desktop. Тогда перед работой в Desktop нажимайте **Fetch origin**, чтобы забрать изменения с сайта.

## Загрузка файлов через сайт GitHub

Самый простой путь, если вы работаете в Kaggle или Colab.

1. Скачайте из Kaggle или Colab ноутбук (`.ipynb`) и файлы результатов (графики, таблицы).
2. Соберите на компьютере папку как в правилах: `lab01/README.md`, `lab01/solution.ipynb`, `lab01/results/...`.
3. Откройте свой репозиторий на GitHub. Нажмите **Add file** → **Upload files**. В пустом репозитории вместо этого будет ссылка **uploading an existing file**.
4. Перетащите **папку** `lab01` целиком в окно браузера. GitHub сохранит структуру папок. (Кнопка *choose your files* выбирает только отдельные файлы, без папок.)
5. Внизу в поле **Commit changes** напишите, что сделали, например `lab01: решение и отчёт`.
6. Оставьте **Commit directly to the main branch** и нажмите **Commit changes**.

Чтобы исправить один файл, откройте его на GitHub и нажмите значок карандаша (**Edit this file**), затем **Commit changes**. Так удобно править README.

Ограничение сайта: файл больше 25 МБ через браузер не загрузится. Ноутбук с десятками картинок в выводе бывает тяжёлым; очистите вывод лишних ячеек перед скачиванием, а картинки сохраните в `results/`.

## Git в терминале

### Вход в GitHub

Удобнее всего войти через [GitHub CLI](https://cli.github.com/): он сам настроит git, токены вручную создавать не придётся.

```bash
gh auth login
```

На вопросы ответьте: **GitHub.com** → **HTTPS** → **Yes** (authenticate Git) → **Login with a web browser**. Скопируйте код из терминала, вставьте его в открывшемся браузере.

Другие способы, если `gh` поставить нельзя:

- **HTTPS и токен.** GitHub → **Settings** → **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**, доступ *Contents: Read and write* к своему репозиторию. При первом `git push` введите логин GitHub, а вместо пароля вставьте токен. Пароль от аккаунта git не примет.
- **SSH-ключ.** `ssh-keygen -t ed25519`, затем содержимое файла `~/.ssh/id_ed25519.pub` добавьте в GitHub → **Settings** → **SSH and GPG keys**. Клонируйте по адресу вида `git@github.com:ivanov/cv-2026-ivanov.git`.

Один раз представьтесь git (имя и почта попадут в историю коммитов):

```bash
git config --global user.name "Ivan Ivanov"
git config --global user.email "ваша-почта-из-github@example.com"
```

### Клонирование

```bash
cd C:/cv                     # или ~/cv на macOS и Linux
git clone https://github.com/ivanov/cv-2026-ivanov.git
cd cv-2026-ivanov
```

### Сохранить и отправить работу

```bash
git status                   # что изменилось; проверьте, что нет данных и весов
git add lab01                # добавить папку лабы
git commit -m "lab01: решение и отчёт"
git push                     # отправить на GitHub
```

`git status` после `git add` покажет зелёным то, что войдёт в коммит. Если там есть `data/`, картинки датасета или файлы `.pt`, остановитесь и прочитайте следующий раздел.

Если вы поменяли файл на сайте GitHub, перед следующей работой заберите изменения: `git pull`.

## Что не коммитить

В репозиторий идёт **ваш код, отчёт и результаты**: ноутбук, README, графики, небольшие таблицы метрик. Не загружайте:

| Что | Почему | Как git узнает, что это не надо брать |
| --- | --- | --- |
| Данные варианта (`variant_07/`, `images/`, `*.zip`) | Сотни мегабайт, у преподавателя они уже есть | Строки `data/`, `variant_*/`, `*.zip` в `.gitignore` |
| Веса моделей (`*.pt`, `*.pth`, `*.onnx`) | Десятки и сотни мегабайт, GitHub не принимает файлы больше 100 МБ | Строки `*.pt`, `*.pth`, `*.onnx` |
| Папки обучения (`runs/`, `lightning_logs/`, `checkpoints/`) | Ultralytics и другие библиотеки кладут туда веса и тысячи картинок | Строки `runs/`, `checkpoints/` |
| Кэш (`__pycache__/`, `.ipynb_checkpoints/`) | Мусор: критерий «Оформление» требует, чтобы его не было | Строки в `.gitignore` |
| Виртуальное окружение (`.venv/`) | Сотни мегабайт, у каждого своё | Строка `.venv/` |
| Токены и пароли (`.env`, `kaggle.json`) | Публичный репозиторий читают все, токен украдут за минуты | Строки `.env`, `kaggle.json` |

`.gitignore` из шаблона уже содержит все эти строки, если вы его скопировали в корень репозитория. Через сайт GitHub `.gitignore` не работает: сайт загрузит всё, что вы перетащили. Поэтому перед загрузкой через браузер проверьте папку глазами.

Нужна картинка из обучения, например кривая loss из `runs/detect/train/results.png`? Скопируйте её в `lab05/results/` и коммитьте оттуда.

### Если данные или веса уже попали в коммит

Коммит ещё **не отправлен** (вы не нажимали Push):

```bash
git rm -r --cached data          # убрать папку из git, файлы на диске останутся
git commit --amend -m "lab01: решение и отчёт"
```

Коммит **уже на GitHub**, и файл меньше 100 МБ: удалите его из репозитория (`git rm -r --cached ...`, коммит, push) и допишите строку в `.gitignore`. В истории файл останется, но в текущей версии репозитория его уже не будет.

## Если push отклонён

| Сообщение | Причина | Что делать |
| --- | --- | --- |
| `! [rejected] main -> main (fetch first)` или `non-fast-forward` | На GitHub есть коммиты, которых нет у вас (например, вы правили README на сайте) | `git pull --rebase`, затем `git push`. В GitHub Desktop: **Fetch origin** → **Pull origin** → **Push origin** |
| `File ... is 123.45 MB; this exceeds GitHub's file size limit of 100.00 MB` | В коммите большой файл, чаще всего веса или архив данных | Уберите файл из коммита (раздел выше) и добавьте его в `.gitignore` |
| `Permission denied` или `Authentication failed` | Git не знает, кто вы, или вы ввели пароль вместо токена | `gh auth login` или войдите заново в GitHub Desktop |
| `Repository not found` | Опечатка в адресе или репозиторий чужой | Проверьте адрес: `git remote -v` |

Если `git pull --rebase` пишет про конфликт, откройте указанный файл, оставьте нужный вариант текста, удалите строки с `<<<<<<<`, `=======`, `>>>>>>>` и выполните `git add файл` и `git rebase --continue`.

## Как проверить время сдачи

Работа считается сданной в момент последнего коммита в её папку на GitHub.

1. Откройте свой репозиторий на GitHub и зайдите в папку `lab01`.
2. Над списком файлов есть строка с последним коммитом, справа от неё указано, когда он сделан («2 hours ago»). Наведите мышь на это время, появится точная дата и время.
3. Полную историю папки показывает кнопка **History** (значок часов) справа в той же строке.

Если строки с вашим коммитом в папке на GitHub нет, работа не сдана, даже если всё лежит у вас на компьютере. Чаще всего вы забыли нажать **Push origin** или `git push`.
